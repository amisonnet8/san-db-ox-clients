# 配布方法

**配布は各言語の標準的な配布方法に従い、共通の配布方法は設けない。**
（ユーザー確定方針）

## 各言語のエコシステムに委ねる

| 言語 | 配布先 | タグ規則 |
| :--- | :--- | :--- |
| Go | Go modules（pkg.go.dev から参照可能） | `go/vX.Y.Z`（`naming.md` 参照） |
| Python | PyPI | `python/vX.Y.Z`（`naming.md` 参照） |
| TypeScript | npm | `typescript/vX.Y.Z` |
| Rust | crates.io | `rust/vX.Y.Z` |
| Java | Maven Central | `java/vX.Y.Z` |

**統一ランチャーやインストーラは作らない。** 「`san-db-ox-clients` を
インストールする」という単一の操作は存在せず、利用者は自分が使う言語の
パッケージマネージャで、その言語のドライバだけを取得する。

## バージョン番号を揃えない

- **言語間でバージョン番号を揃えない。** 各エコシステムの慣習と、その
  言語のドライバ自身の変更履歴に従って独立に上げる。揃えようとすると、
  ある言語に変更が無いのに他言語の変更につられて版を上げることになり、
  「このバージョンで何が変わったか」が意味を失う。
- **ドライバのバージョンと本体（san-db-ox）のバージョンも連動させない。**
  対応関係は「このドライバが実装している `protocol` 番号」（`protocol.md`
  参照）で表し、各言語の README に明記する。バージョン番号自体でこの対応を
  表現しようとしない。

## 本体バイナリは同梱しない

ドライバのパッケージに本体バイナリを同梱しない。各 OS・アーキテクチャ向け
バイナリを同梱すると、パッケージ（Go module・PyPI ホイール・npm パッケージ）
が巨大になり、かつ組み合わせの数だけビルド・配布の手間が増える。利用者は
本体を `testing.md` に記載した方法（GitHub Releases 等）で別途入手する。
